# 将软件界面中文化

## Goal

将 Canopy 的用户界面统一改为简体中文，使中文用户可以完成会话创建、历史浏览、树形分支操作、回复生成和全局设置等现有流程，无需理解英文界面文案。

## Background

- 当前应用是 React/Vite/Tauri 桌面应用，没有国际化框架或语言资源文件。
- 用户决定本次仅提供简体中文，不保留英文界面，也不提供语言切换。
- 主要用户界面集中在会话工作区、消息/分支操作和全局设置；生成生命周期已有部分中文，其余用户文案仍以英文为主。
- 用户可见错误既来自前端兜底与流程状态，也来自 Rust `CommandError.message`；后者经 TypeScript 桥接验证后直接展示。
- `index.html:2` 当前声明 `lang="en"`。

## Requirements

### R1. 单语言范围

- 应用仅显示简体中文界面，不新增国际化依赖、语言资源系统、语言状态或切换入口。
- 品牌名 `Canopy`、`OpenAI`、`API` 等通用技术缩写可以保留；URL、模型标识、API 密钥状态值及其他技术值不得被翻译或改写。

### R2. 会话工作区

- 中文化历史记录、会话树、侧栏控制、新建会话、归档、生成/取消生成、加载、空状态、重试、关闭提示和编辑/创建分支等用户文案。
- 将消息角色显示为中文标签，但不得修改角色枚举、持久化数据或用户消息内容。
- 现有生成生命周期文案继续使用简体中文，并与新增文案保持术语一致。

### R3. 全局设置

- 中文化设置入口、对话框标题/说明、服务提供商配置、表单标签与帮助文本、只读/生成中状态、保存/删除操作和删除确认。
- `OpenAI`、端点 URL、模型标识和 `API` 等技术内容按 R1 保留。

### R4. 错误与状态

- 中文化前端定义的兜底错误、流程错误、不可用原因以及 Rust 命令边界产生的安全用户错误摘要。
- 保持 `CommandError.code`、`retryable`、`details`、IPC 字段形状和所有控制流语义不变；组件仍不得通过错误消息文本决定行为。
- 用户界面不得直接显示英文机器错误码；诊断和测试内部使用的稳定错误码不受影响。

### R5. 无障碍与文档语言

- 中文化屏幕阅读器标签、图标按钮名称、工具提示、加载状态和表单可访问名称。
- 将 HTML 根元素语言声明改为 `zh-CN`。

### R6. 行为与数据兼容

- 不改变现有会话树、分支、生成、归档、设置、凭据处理或持久化行为。
- 不修改已有会话标题、用户消息、模型回复或数据库内容。

### R7. 测试与质量

- 更新所有依赖用户文案或错误摘要的前端、Rust 和跨边界测试。
- 使用可访问角色与中文名称验证主要操作，不以宽泛快照替代行为断言。
- 完成英文残留审计，并区分允许保留的技术值、内部标识和真正的用户界面文案。

## Acceptance Criteria

- [x] AC1：启动应用后，HTML 根元素声明 `lang="zh-CN"`，所有现有主要界面区域均使用简体中文。
- [x] AC2：用户可以用简体中文完成新建会话、选择历史会话、生成/取消回复、归档、编辑为新分支和创建分支。
- [x] AC3：用户可以用简体中文理解并操作全局设置的查看、保存、删除和受限状态。
- [x] AC4：可见文案、工具提示、表单标签、无障碍名称、加载/空状态、确认对话框与实际运行时错误摘要均为简体中文。
- [x] AC5：错误码、重试属性、结构化详情、IPC 结构、数据模型与现有业务行为没有变化，界面不再暴露英文机器错误码。
- [x] AC6：品牌名、技术缩写、URL、模型标识、用户内容和模型输出保持原值。
- [x] AC7：现有响应式布局和交互测试均通过，未发现中文文案导致的不可操作状态；真实桌面窗口视觉检查仍作为人工烟测项。
- [x] AC8：任务文件格式检查、ESLint、TypeScript、前端测试、生产构建、Rust 格式检查与 Rust 测试全部通过；全仓 Prettier 仅受任务前已有的 `.claude/settings.local.json` 阻挡。

## Out of Scope

- 中英文切换、运行时语言检测、翻译资源加载或其他语言支持。
- 修改用户已有内容、模型生成内容或持久化数据。
- 改变后端命令、数据结构、错误分类、重试策略或生成业务流程。
- 对整体视觉设计、布局或功能导航进行无关重构。
