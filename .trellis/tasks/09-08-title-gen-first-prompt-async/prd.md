# 对话标题生成：仅用首条用户提示词并异步执行

## Goal

自动标题生成改为：**只使用该会话中用户发送的首条消息**作为标题模型的输入，并且与助手首条回复的生成**并行执行**（不再等回复完成），使标题更早出现；同时参照主流产品实践改写发给标题模型的提示词。

## Requirements

- R1 标题模型的输入仅为会话的**首条用户消息**（截断、转义规则沿用现有限制），不再包含助手回复内容。
- R2 标题生成在**首条回复开始生成时**即触发，与回复流式生成并行；不再以首条回复 `Completed` 为前置条件。
- R3 幂等且防覆盖：自动标题最多生效一次；若用户在标题返回前已手动改名（或占位标题已被替换），自动标题**不得覆盖**（采用比较-交换语义）。
- R4 提示词改写：参照主流实践（见 `research/title-generation-practices.md`），system/user 提示词面向“仅首条用户消息”场景重写，明确只输出标题、无引号/解释/前缀、长度上限、跟随用户语言。
- R5 失败静默：标题生成失败（网络、模型、空结果）只记日志，不影响回复生成与 UI；占位标题保留。
- R6 设置项行为不变：`auto_generate_title` 开关与 `title_model_binding`（跟随会话/指定模型）解析顺序保持不变；设置页文案需与新触发时机匹配（不再是“首次问答之后”）。
- R7 首条回复失败或被取消时，标题生成不受影响（输入不依赖回复）；允许标题在回复失败的情况下依然生成成功。
- R8 不改变前端占位标题（首条消息截断 40 字符）与 `conversation://title-updated` 事件的现有协议形状。

## Acceptance Criteria

- [ ] AC1 新会话发送首条消息后，标题请求与助手回复请求**并发发出**（日志/测试可验证标题任务在回复完成前已启动）。
- [ ] AC2 标题请求的消息载荷中只包含首条用户消息，不含任何助手内容（快照/单元测试验证 prompt 构造）。
- [ ] AC3 标题在首条回复流式输出**进行中**即可通过 `conversation://title-updated` 到达前端并就地更新。
- [ ] AC4 用户在标题返回前手动改名，自动标题返回后不覆盖手动标题（CAS 测试）。
- [ ] AC5 首条回复失败/取消后重试发消息，不会生成第二个自动标题；标题已由 LLM 生成过的会话不再重复触发。
- [ ] AC6 `auto_generate_title=false` 时完全不发起标题请求；`title_model_binding` 的解析优先级（设置绑定 → 会话绑定 → 活动 provider）不变。
- [ ] AC7 设置页描述文案（en/zh）更新为新触发时机的表述。
- [ ] AC8 相关测试（`title.rs`、`title_prompt.rs` 等）更新并通过；lint、type-check、前后端测试全绿。
- [ ] AC9 `.trellis/spec` 中 auto-title 相关契约（触发时机、上下文、prompt 形状、防覆盖）同步更新。

## Out of Scope

- 不改标题模型绑定 UI 的交互结构（仅文案）。
- 不引入标题重新生成/手动刷新标题功能。
- 不改占位标题的 40 字符截断规则。

## Notes

- 调研结论见 `research/title-generation-practices.md`：仅首条用户消息 + 并行触发 + CAS 防覆盖均为已验证的主流模式。
- 技术设计见 `design.md`，执行计划见 `implement.md`。
